# 1.2.0 (2026-11-27)

- Add a `bundle` command that writes a multi-file spec as one resolved document, optionally filtered by tags (`-t`) and converted to another version (`--to`), failing on an unresolvable `$ref` or an invalid document
- Add `--ref-root` to `generate`, `convert` and `bundle`, letting external `$ref`s reach files outside the spec file's directory
- Add `WithAuth` to go_net_http_client to supply bearer token and API key credentials for operations with a security requirement
- Give go_net_http_server handlers the request and response writer via `RequestFromContext`/`ResponseWriterFromContext`, e.g. to set response headers or stream a response
- Add a `tags` argument to the buildDocComment built-in and a new propertyDescription built-in for generator authors
- Fail on an unresolvable external `$ref` instead of skipping it and silently losing models and operations
- Bundle components of external files into the same components section, only when reachable; equal names with different content are now an error instead of getting a `_2` suffix
- Generate open enums in both Go generators for `anyOf`/`oneOf` of a string enum and a string, and for `x-extensible-enum` (types and signatures change for such schemas)
- Make both Go generators reject a JSON object lacking a required property, and keep `additionalProperties` declared next to `properties`
- Check minimum/maximum/length/pattern/format constraints of path, query, header and cookie parameters in go_net_http_server
- Require the `Bearer` scheme in the Go, Kotlin Ktor and Python Tornado servers: another scheme or a bare token now counts as missing credentials (401)
- Limit the error body kept by go_net_http_client to `MaxErrorBodySize` (64 KiB) and leave it out of `ResponseError.Error()`
- Document properties in all built-in generators with the description written next to their `$ref`, and add `@return` to Kotlin and TypeScript operation comments
- Fix path item `$ref`s to other files losing their operations, security requirements or tag descriptions
- Fix go_net_http_server generating code that didn't compile for optional multipart, urlencoded or text request bodies
- Fix go_net_http_client panicking on a `nil` optional multipart or urlencoded body, and sending a named array form field as a single value
- Fix both Go generators failing or emitting uncompilable code for parameters, form fields and constraints that reference named scalar or array schemas
- Fix a named date-time schema in both Go generators being encoded as `{}` and failing to decode
- Fix multi-line operation descriptions breaking the code generated by the Ruby generators

# 1.1.0 (2026-09-29)

- Stream raw (binary) request/response bodies instead of buffering them in all generators, sending wildcard media types as `application/octet-stream`; go_net_http_server serves raw responses via `http.ServeContent` (Range, conditional requests, Content-Disposition) and checks the request Content-Type (415 on mismatch) (handler/client signatures change for raw-body operations)
- Generate a per-status sealed result type for operations with several 2xx responses in all generators, so the server picks e.g. 200 vs 202 at runtime and the client sees which one it got (signatures change for such operations)
- Add route listing to go_net_http_server: a per-tag `XRoutes()` table, a combined `server.Routes()`, `OpenAPISpec()`, and `RegisterXRoutes` accepting a `server.Router` interface (`*http.ServeMux` still satisfies it)
- Fix buildDocComment's `/** */` style breaking the generated file when a description contains `*/` or `/*` (e.g. `application/*`)
- Fix both Go generators emitting an unused models import into files whose only types are `[]byte`, which didn't compile

- Fix relative/same-origin `baseUrl` support in ruby_faraday_client_generator and typescript_fetch_client_generator, which previously threw a `TypeError`
- Fix loading generated Ruby server and client bundles in the same process colliding on a shared flat runtime module
- Fix ruby_faraday_client_generator silently dropping a connection's base path on every request

# 0.10.0 (2026-08-12)

- Add unwrapSchema, resolveUnionDispatch, buildDocComment (with multi-language comment-style support - /** */, //, ///, #), and disambiguateName engine built-ins for generator authors
- Substantially improve oneOf/anyOf/union and parameter handling across all three generators - catch-all, enum-typed, array-typed, and date/date-time-typed parameters, deepObject range-filter query params, name-collision disambiguation for synthetic types, and numerous crash fixes - verified against real-world specs (DigitalOcean, Stripe's full 170K-line API)
- Add an ApiClient bundle class to the Kotlin client generator (one instance of every tag's client, from a shared HttpClient/base URL), matching the TypeScript client generator
- Resolve non-standard external $ref files referenced next to a spec (a common shape for pre-bundled real-world specs)
- Embed the three built-in generators into the CLI binary (-g builtin:<name>, no local checkout or network access needed); add list-generators, extract, and info commands
- Add a documentation website, with an install → generate → use homepage walkthrough
- Add security scheme (bearer/apiKey) support to the Kotlin server and TypeScript client generators, with recursive nested/array validation and clearer parameter-parsing errors in the Kotlin server generator
- Support OpenAPI 3.0/3.1/3.2 (via a typed internal representation) and Swagger/OpenAPI 2.0 as generation input, plus a new convert command between any of those versions
- Add core built-ins for generator authors: splitPathTemplate, firstSuccessResponse, flattenAllOf (now recursive), resolveDiscriminator, toStringLiteral
- Add typescript_fetch_client_generator: a browser-native fetch-based API client generator with zero dependencies and opt-in runtime response validation
- Install to ~/.local/bin instead of /usr/local/bin, no root/sudo needed
- Generated code is now correctly indented via a forked Inja engine (indent()/{% filter %}/macros) instead of ad-hoc space-placement - template syntax fully documented
- Kotlin generators no longer nest generated output under a packageName-derived subdirectory - packageName now only sets the `package` declaration
- Fix unescaped wire names/values landing in generated Kotlin/TypeScript string literals and annotations - a spec with `"`/`\` in a property or parameter name could produce broken or unsafe generated code
- Restrict generator/template file access to the working folder - closes path-traversal, absolute-path, and shell-injection escapes an untrusted -g <url> generator could otherwise exploit
- Fix requestBody.required incorrectly defaulting to true instead of OpenAPI 3.0's actual default (false) when absent, in both Kotlin generators
